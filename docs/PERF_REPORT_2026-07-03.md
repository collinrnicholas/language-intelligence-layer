# Loupe Pipeline Performance Report — July 3, 2026

Benchmark session: NNA "project pge" (6 transcript notes, 35 screenshots, 158 events,
audio embedded). Gateway: local dev gateway → OpenAI (gpt-4o / gpt-4o-mini).
All numbers measured, not estimated, via the per-call timing instrumentation
(`[LLM:timing]` lines, persisted per run as `debug/00_timings.json` / `debug/11_timings.json`).

## Before / after

| Metric | Original (sequential) | After — cold cache | After — warm cache |
|---|---|---|---|
| analyze wall time | ~81s (sum of call latencies; calls ran serially) | **37.9s** | **0.1s** (12/12 hits) |
| build-this wall time | ~10.8s | **8.3s** | **0.1s** (3/3 hits) |
| end-to-end | ~92s | **46s** | **0.2s** |
| model calls | 12 + 3 | 12 + 3 (unchanged) | 12 + 3, all cached |
| premium calls | 10 | 10 (7 analyze + 3 build) | 0 billed |

The "original" column is the measured sum of per-call latencies — an accurate
reconstruction of the fully sequential pipeline (every stage awaited the previous
one), not a guess. Cold-cache end-to-end is ~2× faster; a re-run on an unchanged
session (same prompts, same models) is effectively free.

## What changed in this pass

1. **Retry + empty-content guard in `callLLM`** (2 attempts, 500ms backoff).
   Fixed a real, observed quality bug: a transient gateway failure returned empty
   content in 210ms, the target batch swallowed it, and 4 of 5 narrated findings
   shipped with **no generated targets** (template fallback). With the retry, all
   narrated findings get targets.
2. **Session understanding ∥ content enumeration** in `analyze` (were sequential;
   both feed target generation but are independent — one reads the transcript,
   the other reads the screenshot). Saves ~2–4s per narrated run.
3. **Shared ContextPack** (`ai/context-pack.ts`): the sorted-transcript block was
   rebuilt identically in 4 stages; now computed once per notes array and reused.
   Prompt bytes unchanged, so LLM cache keys are unaffected.
4. **Deterministic PNG re-encode** (`content-enumerator`): `sips` embeds a
   timestamp in PNG output, so identical screenshots hashed differently every run
   and defeated the cache for enumeration *and* every downstream prompt embedding
   its output. Conversion is now cached by input hash (`~/.loupe/cache/png/`).
5. **Critic prompt timestamp neutralized**: the brief footer's `Generated by
   Loupe — <ISO date>` was the one byte-level difference busting the critic's
   cache. Stripped from the critic's *prompt* only; the shipped document keeps it.
6. **Vision dropped for purely-functional target batches**: functional targets
   are symptom-and-diagnose by rule, so screenshots add nothing; dropping them
   converts a premium vision call into a standard text call. Layout/visual
   batches keep screenshots (quality gate).
7. **Whisper transcription cache** by audio hash (`~/.loupe/cache/transcribe/`) —
   re-analyzing the same capture never re-uploads multi-MB audio.
8. **Instrumentation completed**: error field on timing lines, per-run timing
   debug artifacts (`00_timings.json`, `11_timings.json`), end-of-run summary
   (`AI calls: N total · Xs model time · N cache hits · N premium`).

Already in place before this pass (verified, kept): parallel persona reviewers,
parallel target batches, parallel product-reasoning ∥ finding-relationships,
prompt-hash response cache in `callLLM` (`LOUPE_DISABLE_LLM_CACHE=1` to bypass),
unified product-reasoning call (goal-context + synthesis in one), critic skip when
no BUILD findings.

## Cache correctness

Key = SHA-256 over task, routed model, prompt hash, system-prompt hash, response
format, maxTokens, temperature, model preference, prompt version, meta, and
per-image hashes. Invalidates automatically when:
- prompt template changes (prompt bytes change),
- model routing changes (routed model in key),
- session file changes (transcript/evidence are embedded in prompts),
- goal mode changes (goal is embedded in the product-reasoning prompt).

## Quality verification (NNA criteria)

Final `build-prompt.md` from the optimized pipeline:
- ✅ Complete quotes — stitched full sentences with timestamps ("First thing that
  we're going to look at is we have the plans that have been uploaded…")
- ✅ 2 BUILD findings (1 primary + 1 conditional follow-up) — within the 2–3 band
- ✅ UX/Product Synthesis present, all six subsections, session-specific
- ✅ No blind CSS for layout findings — B1/B2 are outcome-first, explore-first,
  with "propose 2–3 ranked approaches" and "do not implement until chosen"
- ✅ Documents prioritized over architectural plans (reviewer's stated goal folded
  into B1 as the "why"; B2 conditional on B1)
- ✅ Claude Code-ready: locate-the-code instructions, constraints, acceptance
  criteria, Also-Detected quarantined as review-only

## Intentionally NOT optimized (quality would suffer)

- **No model downgrades** on narration judge, UX/Product synthesis, prompt critic,
  screenshot-aware target generation, finding relationships, content enumeration —
  all stay premium.
- **Prompt critic stays sequential** after brief assembly — it reviews the
  assembled document; parallelizing it would be incorrect.
- **Transcript stitching stays an LLM call** (gpt-4o-mini) — sentence-boundary
  judgment is semantic; quality held in benchmarks.
- **Targets are generated per narrated finding** even though `build-this` may
  later merge some — merging happens per goal/selection at build time; pre-merging
  in analyze would couple the stages and change BUILD semantics.
- **Full transcript still ships to every reasoning stage** — it is small (~0.5KB
  here) and the "compressed transcript" tradeoff isn't worth the quote-fidelity
  risk.

## Known non-issue observed

Judge verdicts vary slightly across cold runs (5 vs 7 narrated of ~16 candidates)
— temperature-level nondeterminism that classifyAndMerge collapses to the same
2-finding BUILD set. Warm-cache runs are fully deterministic.
